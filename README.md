# 🍱 冷凍弁当 在庫管理

冷凍弁当（ベルーナなど）の在庫を、配送予定と食事ルールから自動で計算するアプリです。
**GitHub Pages で公開できる静的サイト**で、サーバーもデータベースも不要。GitHub の無料プランだけで使えます。

---

## できること

| 機能 | 内容 |
| --- | --- |
| 在庫の自動計算 | 基準の在庫 ＋ 配送 − 食事 で、いまの在庫と今後の推移を計算 |
| 配送の登録 | 到着日はランダムでOK。個数は既定 10個（設定で変更可）、1件ずつ個数も変更可 |
| 食事ルール | 火曜17:00・木曜17:00・土曜12:00 に1食／8月の水曜・第5水曜・水曜の祝日 12:00 に1食 |
| 食べた数の修正 | 予定ごとに ＋/− で修正（0＝食べなかった、2以上＝多く食べた）。メモも残せる |
| 臨時の記録 | 予定外に食べた分、廃棄などの在庫補正、実数での数え直し（棚卸し） |
| カレンダー | 月ごとに 🍱食事・📦配送・その日の終わりの在庫を一覧。日付を押すとその日を編集 |
| 在庫切れ予測 | 「このままだと ○月○日に在庫切れ」を表示。残りが少なくなると色が変わる |
| 祝日の判定 | アプリ内で計算（振替休日・国民の休日を含む）。外部サービス不要 |

### 食事ルールの詳細

- 毎週 **火曜 17:00**／**木曜 17:00**／**土曜 12:00** に 1食
- **8月の水曜**／**第5水曜**／**水曜が祝日** の日は **12:00** に 1食
  - 水曜の条件が重なっても（例：8月の第5水曜）その日は 1食として数えます
  - 条件はすべて設定画面でオン・オフできます

## 使いはじめ

1. アプリを開き、ホームの **「在庫の個数を入力する」** で、いま冷凍庫にある個数を登録します。
2. 配送タブで、到着日と個数（既定10個）を登録します。
3. あとは、食べた数が予定と違ったときにホームやカレンダーで **＋/−** を押して直すだけです。

食べた数が予定どおりなら、操作は不要です（自動で減ります）。

## データの保存方法（3通り）

### 1. この端末に自動保存（既定・設定不要）
変更するたびにブラウザの localStorage へ自動保存されます。同じ端末の同じブラウザで開けば、そのまま続きを使えます。

### 2. バックアップファイル（機種変更・別端末へ移すとき）
設定タブ →「バックアップを書き出す」で JSON ファイルを保存。新しい端末では「バックアップを読み込む」で復元します。

### 3. GitHub同期（複数の端末で同じ在庫を見たいとき・任意）
データを、このリポジトリの `data/inventory.json` にコミットして共有します。

- **読み込みはトークン不要**です。公開ページなので、別の端末でアプリを開くと自動で最新データを読み込みます。
- **保存（コミット）にはアクセストークンが必要**です。

トークンの作り方:

1. GitHub → Settings → Developer settings → **Personal access tokens → Fine-grained tokens** → Generate new token
2. **Repository access**: このリポジトリだけを選択
3. **Permissions → Repository permissions → Contents: Read and write** （これ以外は不要）
4. 生成されたトークンをコピーし、アプリの設定タブ「アクセストークン」に貼り付け

> トークンはお使いの端末のブラウザ（localStorage）にのみ保存され、公開されるページやバックアップJSONには含まれません。
> 共用のパソコンでは「GitHubに保存」を使わず、バックアップファイルでの持ち運びをおすすめします。

「変更を自動でGitHubに保存する」をオンにすると、操作の数秒後にまとめてコミットされます。

## GitHub Pages での公開手順

1. このブランチの内容を `main` ブランチに取り込みます（プルリクエストをマージ、など）。
2. GitHub のリポジトリ → **Settings → Pages** を開きます。
3. **Source** を `Deploy from a branch`、**Branch** を `main` / `/ (root)` にして Save。
4. 1〜2分ほどで公開URLが表示されます。スマホでそのURLを開き、ホーム画面に追加するとアプリのように使えます。

追加の設定やビルドは不要です（`.nojekyll` を置いてあるので、そのまま配信されます）。

## ファイル構成

```
index.html              画面の構造
css/style.css           スタイル（スマホ優先・ダークモード対応）
js/util.js              日付・DOMの共通処理
js/holidays.js          日本の祝日計算（振替休日・国民の休日を含む）
js/engine.js            食事予定の生成と在庫計算
js/store.js             保存（localStorage／JSON／GitHub同期）
js/app.js               画面の組み立てと操作
data/inventory.json     GitHub同期で使うデータファイル
manifest.webmanifest    ホーム画面に追加するための設定
```

## 動作環境

スマートフォン・パソコンの最近のブラウザ（Safari / Chrome / Edge / Firefox）。
外部のライブラリやサービスは使っていないため、オフラインでも一度開いたページはそのまま操作できます。
